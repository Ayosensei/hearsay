# G8 — adaptive policy and real gossip hubs

createPolicy(db, world?) exposes adaptPolicy and gossipHubs with the existing contract. adaptPolicy resolves player/NPC and the NPC's FOLLOWS relationship before writing. Lowballed adds step up to maxMarkup; fair subtracts 0.02 down to minMarkup. Every call increments tries, and fair increments wins. Q81 checks the read counters exactly and markup within 1e-9 before updating: competing changes fail explicitly instead of being overwritten. This is conflict detection, not an automatic retry or distributed transaction. Exact double equality initially rejected the second sequential update because returned decimal precision differed from stored floating-point arithmetic; the tolerance corrects that issue while counters detect intervening adaptations.

Live tests seed Tilda's synthetic test policy at 0.10, verify 0.15/0.20/0.25/0.30/0.30 on successive lowballs, fair reduction and the 0.05 floor. Policy data is isolated by player. Production seed remains the three-NPC stub, so production Tilda/policy requires D1 content.

gossipHubs runs actual FalkorDB PageRank through roQuery on a supplied player graph or the template. On the locked six-NPC test network the observed order is Mira, Tilda, Fenn, Garrick, Brom, Ayla. No ranks are hardcoded in the implementation. Canonical Q70/Q80/Q81 live in queries/policy.ts; the old spike reexports Q70. All three are exercised on real FalkorDB under the previously approved direct-client exception. No schema or dependency changes. UI integration remains pending; G8 does not make Gemini quote adapted prices (dialogue policy guidance is a later integration concern).
